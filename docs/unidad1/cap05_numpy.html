5  Capítulo 5: NumPy y Cálculo Vectorizado

El motor numérico de las finanzas cuantitativas en Python

Resumen

NumPy es la librería sobre la que se construye todo el stack científico de Python (Pandas, SciPy, scikit-learn). En este capítulo entendemos por qué el ndarray reemplaza a las listas para trabajar con números, aprendemos a vectorizar cálculos para eliminar bucles lentos, dominamos el broadcasting y damos nuestros primeros pasos en álgebra lineal, que será la columna vertebral de la optimización de portafolios del Módulo 2.

6 Introducción

Hasta ahora venimos representando datos financieros con listas y diccionarios de Python. Nos sirvieron para aprender a programar, pero tienen un problema serio: son lentas y verbosas cuando hay que hacer cuentas sobre miles de números. Y en finanzas, siempre hay miles de números: años de cotizaciones diarias, paneles de cientos de activos, millones de trayectorias en una simulación.

Acá entra NumPy (de Numerical Python). Es la librería que le da a Python la capacidad de hacer cálculo numérico a la velocidad de un lenguaje compilado como C, pero con la comodidad de escribir Python. No es una librería más: es la base sobre la que están construidos Pandas, SciPy, scikit-learn y prácticamente todo lo que vas a usar de acá en adelante. Cuando en el Capítulo 6 hagas pd.DataFrame, por debajo hay arrays de NumPy; cuando en el Capítulo 8 optimices un portafolio de Markowitz, vas a estar multiplicando matrices de NumPy.

TipLa idea de fondo

Programar con NumPy es cambiar el chip: en vez de pensar “recorré la lista elemento por elemento y hacé la cuenta”, pensás “aplicá esta operación a todo el vector de una”. Eso se llama vectorización, y es la habilidad central de este capítulo.

import numpy as np

Por convención universal, NumPy se importa como np. Vas a ver ese np. en todo el libro (y en todo el ecosistema de Python científico), así que conviene acostumbrarse desde ya.

7 El problema: las listas no fueron hechas para calcular

Imaginá que tenés los precios de cierre de una acción durante cinco días y querés calcular el retorno simple diario, \(R_t = P_t / P_{t-1} - 1\). Con listas puras, tenés que escribir un bucle:

precios = [100.0, 102.5, 101.0, 103.5, 105.0]

retornos = []
for i in range(1, len(precios)):
    retornos.append(precios[i] / precios[i-1] - 1)

print(retornos)
[0.02499999999999991, -0.014634146341463428, 0.024752475247524774, 0.01449275362318847]

Funciona, pero fijate todo lo que tuviste que hacer: crear una lista vacía, manejar índices, acordarte de arrancar en 1. Y esto es para una sola acción y cinco días. Con NumPy, el mismo cálculo es una línea que se lee casi como la fórmula matemática:

precios = np.array([100.0, 102.5, 101.0, 103.5, 105.0])

retornos = precios[1:] / precios[:-1] - 1

print(retornos)
[ 0.025      -0.01463415  0.02475248  0.01449275]

precios[1:] es “todos los precios desde el segundo” (\(P_t\)) y precios[:-1] es “todos menos el último” (\(P_{t-1}\)). NumPy divide los dos vectores elemento a elemento automáticamente. Sin bucles, sin índices, sin listas vacías. Esto no es solo más corto: sobre datos reales es decenas o cientos de veces más rápido, porque la operación corre en código C optimizado en lugar de un bucle interpretado de Python.

8 El ndarray: qué es y por qué es distinto

El objeto central de NumPy es el array (ndarray, de N-dimensional array). A primera vista se parece a una lista, pero tiene tres diferencias que lo cambian todo:

  1. Es homogéneo: todos los elementos son del mismo tipo (todos float64, todos int, etc.). Una lista de Python puede mezclar números, strings y objetos; un array no. Esa restricción es justamente lo que lo hace rápido.
  2. Es contiguo en memoria: los datos se guardan en un bloque compacto y ordenado de RAM, no desperdigados con punteros como en una lista. El procesador puede recorrerlos de corrido.
  3. Opera vectorizado: las operaciones aritméticas se aplican a todo el array de una sola vez, apoyándose en instrucciones de bajo nivel del procesador.
a = np.array([10, 20, 30, 40])

print("Array:   ", a)
print("Tipo:    ", type(a))
print("dtype:   ", a.dtype)     # tipo de los elementos
print("shape:   ", a.shape)     # forma (dimensiones)
print("ndim:    ", a.ndim)      # cantidad de dimensiones
print("size:    ", a.size)      # cantidad total de elementos
Array:    [10 20 30 40]
Tipo:     <class 'numpy.ndarray'>
dtype:    int64
shape:    (4,)
ndim:     1
size:     4

El dtype (data type) es un concepto clave: le dice a NumPy exactamente cuántos bytes ocupa cada número y cómo interpretarlos. En finanzas trabajamos casi siempre con float64 (números reales de doble precisión), que es el default para decimales.

Notashape: la forma manda

El atributo .shape es una tupla que describe las dimensiones. Un vector de 4 elementos tiene shape (4,); una matriz de 3 filas por 2 columnas tiene shape (3, 2). Cuando algo falla en NumPy, el 90% de las veces es un problema de shapes que no encajan. Acostumbrate a mirar .shape como primer paso de debugging.

8.1 Crear arrays

Rara vez vas a escribir los números a mano. NumPy trae funciones para generar los arrays más comunes:

# Desde una lista
np.array([1.0, 2.0, 3.0])

# Rango de valores (como range, pero array): inicio, fin (excluido), paso
plazos = np.arange(0, 12, 3)          # [0, 3, 6, 9] meses
print("arange:  ", plazos)

# N valores equiespaciados entre dos extremos (útil para grillas)
grilla = np.linspace(0, 1, 5)         # 5 puntos entre 0 y 1
print("linspace:", grilla)

# Arrays de ceros y unos (útiles para inicializar acumuladores)
print("zeros:   ", np.zeros(4))
print("ones:    ", np.ones(3))

# Matriz identidad (aparecerá en álgebra de portafolios)
print("identidad:\n", np.eye(3))
arange:   [0 3 6 9]
linspace: [0.   0.25 0.5  0.75 1.  ]
zeros:    [0. 0. 0. 0.]
ones:     [1. 1. 1.]
identidad:
 [[1. 0. 0.]
 [0. 1. 0.]
 [0. 0. 1.]]

8.2 Arrays de varias dimensiones

Un vector es 1D; una matriz es 2D. En finanzas la matriz más importante es el panel de retornos: filas = fechas, columnas = activos.

# Retornos mensuales de 3 activos durante 4 meses (4 filas x 3 columnas)
R = np.array([
    [0.02, -0.01,  0.03],
    [0.01,  0.02, -0.02],
    [-0.03, 0.01,  0.04],
    [0.02,  0.00,  0.01],
])

print("Panel de retornos:\n", R)
print("\nShape:", R.shape, "→ 4 fechas, 3 activos")
Panel de retornos:
 [[ 0.02 -0.01  0.03]
 [ 0.01  0.02 -0.02]
 [-0.03  0.01  0.04]
 [ 0.02  0.    0.01]]

Shape: (4, 3) → 4 fechas, 3 activos

9 Números aleatorios: el generador moderno

Buena parte de las finanzas computacionales consiste en simular escenarios, y para eso necesitamos números aleatorios. NumPy recomienda hoy usar un generador explícito, creado con np.random.default_rng(). Le pasamos una semilla (seed) para que los resultados sean reproducibles: la misma semilla da siempre los mismos “azares”, lo cual es fundamental para que tus ejemplos y los de tus compañeros coincidan.

rng = np.random.default_rng(seed=42)

# 5 retornos diarios simulados: media 0.05%, desvío 1.5%
retornos_sim = rng.normal(loc=0.0005, scale=0.015, size=5)
print("Retornos simulados:", retornos_sim)

# Una matriz 3x3 de números uniformes entre 0 y 1
print("\nUniformes:\n", rng.random((3, 3)))
Retornos simulados: [ 0.00507076 -0.01509976  0.01175677  0.01460847 -0.02876553]

Uniformes:
 [[0.97562235 0.7611397  0.78606431]
 [0.12811363 0.45038594 0.37079802]
 [0.92676499 0.64386512 0.82276161]]
AdvertenciaVas a ver np.random.seed() en código viejo

Mucho código (y capítulos previos de versiones anteriores de este libro) usa el estilo antiguo np.random.seed(42) y np.random.normal(...). Funciona, pero está considerado legacy. El estilo moderno con default_rng() es más robusto y es el que vas a encontrar en la documentación actual. Usá rng. de acá en adelante.

10 Indexado, slicing y máscaras booleanas

Acceder a partes de un array es donde NumPy se pone realmente potente.

10.1 Slicing básico

Funciona como en las listas, con [inicio:fin:paso], pero se extiende a varias dimensiones separando con comas: matriz[filas, columnas].

# Usamos el panel R de antes
print("Primera fila (retornos de la fecha 0):", R[0])
print("Primera columna (activo 0 en el tiempo):", R[:, 0])
print("Submatriz (2 primeras fechas, 2 primeros activos):\n", R[:2, :2])
print("Último retorno del último activo:", R[-1, -1])
Primera fila (retornos de la fecha 0): [ 0.02 -0.01  0.03]
Primera columna (activo 0 en el tiempo): [ 0.02  0.01 -0.03  0.02]
Submatriz (2 primeras fechas, 2 primeros activos):
 [[ 0.02 -0.01]
 [ 0.01  0.02]]
Último retorno del último activo: 0.01

La coma es la clave: R[:, 0] significa “todas las filas, columna 0”. Poder pedir una columna entera de un panel sin bucles es exactamente lo que necesitamos para analizar un activo a lo largo del tiempo.

10.2 Máscaras booleanas: filtrar por condición

Esta es una de las herramientas más usadas en análisis financiero. Una comparación sobre un array devuelve un array de True/False, y podemos usar ese array como “filtro”:

retornos_diarios = np.array([0.012, -0.008, 0.003, -0.021, 0.015, -0.004])

# La comparación genera una máscara booleana
mascara_perdidas = retornos_diarios < 0
print("Máscara (días con pérdida):", mascara_perdidas)

# Usamos la máscara para quedarnos solo con esos elementos
perdidas = retornos_diarios[mascara_perdidas]
print("Retornos negativos:        ", perdidas)

print(f"\nDías con pérdida: {mascara_perdidas.sum()} de {retornos_diarios.size}")
print(f"Pérdida promedio: {perdidas.mean():.2%}")
Máscara (días con pérdida): [False  True False  True False  True]
Retornos negativos:         [-0.008 -0.021 -0.004]

Días con pérdida: 3 de 6
Pérdida promedio: -1.10%

Fijate el truco de mascara_perdidas.sum(): como True vale 1 y False vale 0, sumar una máscara booleana cuenta cuántas condiciones se cumplen. Es un patrón que vas a repetir mil veces (¿cuántos días superaron el VaR?, ¿cuántos activos rindieron más que el mercado?, etc.).

11 Vectorización: pensar en vectores, no en bucles

Ya vimos la idea con los retornos. Generalicémosla. Las operaciones aritméticas (+, -, *, /, **) y las funciones de NumPy (np.log, np.exp, np.sqrt…) se aplican elemento a elemento sobre todo el array.

precios = np.array([100.0, 102.5, 101.0, 103.5, 105.0])

# Retorno logarítmico: r_t = ln(P_t / P_{t-1}), en una línea
ret_log = np.log(precios[1:] / precios[:-1])
print("Retornos log:", ret_log)

# Convertir un vector entero de tasas anuales a mensuales, todo de una
tasas_anuales = np.array([0.40, 0.35, 0.50, 0.45])
tasas_mensuales = (1 + tasas_anuales) ** (1/12) - 1
print("Tasas mensuales equivalentes:", np.round(tasas_mensuales, 4))
Retornos log: [ 0.02469261 -0.01474228  0.0244511   0.01438874]
Tasas mensuales equivalentes: [0.0284 0.0253 0.0344 0.0314]
TipLa regla de oro

Si te encontrás escribiendo un for que recorre un array para hacer una cuenta en cada elemento, casi siempre hay una versión vectorizada más corta y mucho más rápida. Antes de escribir el bucle, preguntate: “¿puedo aplicarle esto al array entero?”

11.1 ¿Cuánto más rápido es, en serio?

No es una diferencia cosmética. Comparemos sumar el cuadrado de un millón de números con un bucle de Python contra NumPy:

import time

datos = rng.normal(size=1_000_000)

# Versión con bucle Python
t0 = time.perf_counter()
suma = 0.0
for x in datos:
    suma += x**2
t_bucle = time.perf_counter() - t0

# Versión vectorizada
t0 = time.perf_counter()
suma_np = np.sum(datos**2)
t_numpy = time.perf_counter() - t0

print(f"Bucle Python:  {t_bucle*1000:7.1f} ms")
print(f"NumPy:         {t_numpy*1000:7.1f} ms")
print(f"NumPy es ~{t_bucle/t_numpy:.0f}x más rápido")
Bucle Python:    293.8 ms
NumPy:             4.0 ms
NumPy es ~73x más rápido

Sobre un millón de datos la diferencia es de uno a dos órdenes de magnitud. En una simulación de Monte Carlo con millones de trayectorias (Capítulo 13), esto es la diferencia entre que tu código termine en segundos o en horas.

¿De dónde sale esa diferencia? Del trabajo repetido que hace el intérprete. En el bucle de Python, cada una del millón de vueltas repite la misma burocracia: mirar qué tipo tiene x (¿es int? ¿float? ¿string?), desempaquetar el valor del objeto que lo envuelve, decidir qué operación “elevar al cuadrado” corresponde a ese tipo, ejecutarla, y volver a empaquetar el resultado en un objeto nuevo. Un millón de elementos, un millón de veces la misma verificación. NumPy hace esa burocracia una sola vez: como el array es homogéneo (todos float64, gracias al dtype), sabe de antemano qué operación aplicar a todos, y delega el recorrido a un bucle compilado en C que barre la memoria contigua a toda velocidad — incluso procesando varios elementos por instrucción del procesador (SIMD). No es que Python “sea lento”: es que le pedimos que vuelva a deducir lo obvio un millón de veces. La vectorización es, en el fondo, mover la decisión fuera del bucle.

12 Reducciones: resumir un array

Una reducción toma muchos números y devuelve pocos: la suma, el promedio, el máximo, el desvío. Son la base de toda la estadística descriptiva.

ret = np.array([0.012, -0.008, 0.003, -0.021, 0.015, -0.004])

print(f"Suma (retorno acumulado aprox): {ret.sum():.4f}")
print(f"Media:                          {ret.mean():.4f}")
print(f"Desvío estándar (volatilidad):  {ret.std():.4f}")
print(f"Mínimo (peor día):              {ret.min():.4f}")
print(f"Máximo (mejor día):             {ret.max():.4f}")
Suma (retorno acumulado aprox): -0.0030
Media:                          -0.0005
Desvío estándar (volatilidad):  0.0122
Mínimo (peor día):              -0.0210
Máximo (mejor día):             0.0150

12.1 El parámetro axis: el concepto que más confunde (y más importa)

Cuando reducimos una matriz, tenemos que decidir en qué dirección resumimos. Ahí entra axis:

  • axis=0 colapsa las filas → un resultado por columna (por activo).
  • axis=1 colapsa las columnas → un resultado por fila (por fecha).

Con un panel de retornos (filas = fechas, columnas = activos), esto es exactamente lo que necesitamos:

# Panel: 4 fechas x 3 activos
R = np.array([
    [0.02, -0.01,  0.03],
    [0.01,  0.02, -0.02],
    [-0.03, 0.01,  0.04],
    [0.02,  0.00,  0.01],
])

# Retorno medio DE CADA ACTIVO → colapsamos las fechas (axis=0)
print("Media por activo (axis=0):", R.mean(axis=0))

# Volatilidad DE CADA ACTIVO
print("Vol por activo   (axis=0):", R.std(axis=0))

# Retorno DE CADA FECHA (un portafolio equiponderado, por ejemplo) → axis=1
print("Media por fecha  (axis=1):", R.mean(axis=1))
Media por activo (axis=0): [0.005 0.005 0.015]
Vol por activo   (axis=0): [0.02061553 0.01118034 0.02291288]
Media por fecha  (axis=1): [0.01333333 0.00333333 0.00666667 0.01      ]
NotaTruco para no confundirte con axis

axis=0 “apunta hacia abajo” (recorre las filas y deja una fila-resumen), así que el resultado tiene tantos elementos como columnas. Regla mnemotécnica: el eje que ponés en axis es el que desaparece del shape. Si R.shape es (4, 3), entonces R.mean(axis=0).shape es (3,).

13 Broadcasting: operar arrays de distinta forma

¿Qué pasa si querés sumarle un número a todo un array, o restarle a cada columna su propia media? NumPy tiene una regla elegante llamada broadcasting: cuando las formas no coinciden, NumPy “estira” automáticamente el array más chico para que encajen, sin copiar datos de verdad.

El caso más simple ya lo usaste sin darte cuenta:

precios = np.array([100.0, 102.5, 101.0])

# Sumar un escalar a un vector: el escalar se "estira" a todos los elementos
print("Con impuesto del 1%:", precios * 1.01)
Con impuesto del 1%: [101.    103.525 102.01 ]

El caso poderoso es normalizar un panel: restarle a cada activo su media y dividir por su desvío (estandarización), una operación constante en modelos de factores y machine learning financiero.

R = np.array([
    [0.02, -0.01,  0.03],
    [0.01,  0.02, -0.02],
    [-0.03, 0.01,  0.04],
    [0.02,  0.00,  0.01],
])

medias = R.mean(axis=0)   # shape (3,) → una media por activo
desvios = R.std(axis=0)   # shape (3,) → un desvío por activo

# R tiene shape (4,3) y medias shape (3,): broadcasting alinea por columna
R_estandarizado = (R - medias) / desvios

print("Medias por activo:", np.round(medias, 4))
print("\nPanel estandarizado (media 0, desvío 1 por columna):\n",
      np.round(R_estandarizado, 3))
print("\nVerificación — media de cada columna:", np.round(R_estandarizado.mean(axis=0), 10))
Medias por activo: [0.005 0.005 0.015]

Panel estandarizado (media 0, desvío 1 por columna):
 [[ 0.728 -1.342  0.655]
 [ 0.243  1.342 -1.528]
 [-1.698  0.447  1.091]
 [ 0.728 -0.447 -0.218]]

Verificación — media de cada columna: [ 0.  0. -0.]

NumPy vio que R es (4, 3) y medias es (3,), y entendió que tenía que restar medias a cada fila. No tuviste que escribir ningún bucle sobre las 4 fechas.

AdvertenciaCuándo el broadcasting falla

El broadcasting solo funciona si las dimensiones son compatibles: o son iguales, o una de ellas es 1. Si intentás operar un (4, 3) con un (4,) vas a recibir un ValueError: operands could not be broadcast together. La solución suele ser reformar el vector a (4, 1) con vector.reshape(-1, 1) para que se alinee por fila en lugar de por columna. Cuando veas ese error, mirá los shapes.

14 Álgebra lineal: la antesala de Markowitz

Acá NumPy muestra para qué fue diseñado. La optimización de portafolios del Módulo 2 se escribe entera en lenguaje matricial, y NumPy lo implementa directo.

El producto matricial se hace con el operador @ (no con *, que es elemento a elemento). Veamos el cálculo más importante de toda la teoría de portafolios: el retorno esperado de un portafolio, que es el producto entre el vector de pesos \(\mathbf{w}\) y el vector de retornos esperados \(\boldsymbol{\mu}\).

# Pesos del portafolio (40% activo 1, 35% activo 2, 25% activo 3)
w = np.array([0.40, 0.35, 0.25])

# Retornos esperados anuales de cada activo
mu = np.array([0.12, 0.18, 0.08])

# Retorno esperado del portafolio: w · mu (producto punto)
ret_portafolio = w @ mu
print(f"Retorno esperado del portafolio: {ret_portafolio:.2%}")
Retorno esperado del portafolio: 13.10%

Y ahora la estrella: la matriz de covarianzas \(\Sigma\), que resume cómo se mueven juntos los activos y es el corazón de la medición de riesgo. NumPy la calcula con np.cov. Con ella, la varianza del portafolio es la forma cuadrática \(\mathbf{w}^T \Sigma \mathbf{w}\):

# Panel de retornos: activos en FILAS, observaciones en COLUMNAS (rowvar=True, el default de np.cov)
rng = np.random.default_rng(7)
R_hist = rng.normal(loc=[0.001, 0.0015, 0.0008],
                    scale=[0.02, 0.03, 0.015],
                    size=(250, 3)).T   # .T → 3 activos x 250 días

# Matriz de covarianzas (3x3)
Sigma = np.cov(R_hist)

15 De NumPy a Pandas

NumPy es potentísimo, pero tiene una limitación para el trabajo diario: los arrays no tienen etiquetas. En R[:, 0] vos sabés que la columna 0 es “el activo A” porque te lo acordás, no porque el array lo diga. Cuando manejás decenas de activos con fechas de por medio, eso se vuelve un problema.

Ahí entra Pandas (Capítulo 6): pone etiquetas (nombres de columnas y un índice de fechas) encima de los arrays de NumPy. Un DataFrame es, en el fondo, un array de NumPy con nombres. Por eso todo lo que aprendiste acá —vectorización, broadcasting, axis, máscaras booleanas— se traslada casi idéntico a Pandas. No estás aprendiendo dos cosas: estás aprendiendo NumPy, y Pandas es NumPy con etiquetas.

16 Errores comunes

AdvertenciaTrampas frecuentes con NumPy
  • Confundir * con @: A * B multiplica elemento a elemento; A @ B es el producto matricial. Para portafolios casi siempre querés @.
  • Copias vs. vistas: un slice como b = a[:2] no copia los datos, es una vista. Si modificás b, modificás a. Si necesitás una copia independiente, usá a[:2].copy().
  • Olvidarse del axis: R.mean() sin axis promedia todos los elementos y te da un solo número, no uno por activo. Casi siempre querés especificar axis.
  • Enteros donde querías decimales: np.array([1, 2, 3]) crea un array de enteros; dividirlo puede truncar en algunos contextos. Escribí 1.0 o pasá dtype=float para asegurarte de trabajar con float64.

# Introducción

Hasta ahora venimos representando datos financieros con **listas** y **diccionarios** de Python. Nos sirvieron para aprender a programar, pero tienen un problema serio: son lentas y verbosas cuando hay que hacer cuentas sobre miles de números. Y en finanzas, *siempre* hay miles de números: años de cotizaciones diarias, paneles de cientos de activos, millones de trayectorias en una simulación.

Acá entra **NumPy** (de *Numerical Python*). Es la librería que le da a Python la capacidad de hacer cálculo numérico a la velocidad de un lenguaje compilado como C, pero con la comodidad de escribir Python. No es una librería más: es la base sobre la que están construidos Pandas, SciPy, scikit-learn y prácticamente todo lo que vas a usar de acá en adelante. Cuando en el Capítulo 6 hagas `pd.DataFrame`, por debajo hay arrays de NumPy; cuando en el Capítulo 8 optimices un portafolio de Markowitz, vas a estar multiplicando matrices de NumPy.

::: {.callout-tip title="La idea de fondo"}
Programar con NumPy es cambiar el chip: en vez de pensar *"recorré la lista elemento por elemento y hacé la cuenta"*, pensás *"aplicá esta operación a todo el vector de una"*. Eso se llama **vectorización**, y es la habilidad central de este capítulo.
:::

```{python}
#| label: setup
import numpy as np
```

Por convención universal, NumPy se importa como `np`. Vas a ver ese `np.` en todo el libro (y en todo el ecosistema de Python científico), así que conviene acostumbrarse desde ya.

# El problema: las listas no fueron hechas para calcular

Imaginá que tenés los precios de cierre de una acción durante cinco días y querés calcular el retorno simple diario, $R_t = P_t / P_{t-1} - 1$. Con listas puras, tenés que escribir un bucle:

```{python}
#| label: listas-loop
precios = [100.0, 102.5, 101.0, 103.5, 105.0]

retornos = []
for i in range(1, len(precios)):
    retornos.append(precios[i] / precios[i-1] - 1)

print(retornos)
```

Funciona, pero fijate todo lo que tuviste que hacer: crear una lista vacía, manejar índices, acordarte de arrancar en `1`. Y esto es para una sola acción y cinco días. Con NumPy, el mismo cálculo es una línea que se lee casi como la fórmula matemática:

```{python}
#| label: numpy-vectorizado
precios = np.array([100.0, 102.5, 101.0, 103.5, 105.0])

retornos = precios[1:] / precios[:-1] - 1

print(retornos)
```

`precios[1:]` es "todos los precios desde el segundo" ($P_t$) y `precios[:-1]` es "todos menos el último" ($P_{t-1}$). NumPy divide los dos vectores **elemento a elemento** automáticamente. Sin bucles, sin índices, sin listas vacías. Esto no es solo más corto: sobre datos reales es **decenas o cientos de veces más rápido**, porque la operación corre en código C optimizado en lugar de un bucle interpretado de Python.

# El `ndarray`: qué es y por qué es distinto

El objeto central de NumPy es el **array** (`ndarray`, de *N-dimensional array*). A primera vista se parece a una lista, pero tiene tres diferencias que lo cambian todo:

1. **Es homogéneo**: todos los elementos son del mismo tipo (todos `float64`, todos `int`, etc.). Una lista de Python puede mezclar números, strings y objetos; un array no. Esa restricción es justamente lo que lo hace rápido.
2. **Es contiguo en memoria**: los datos se guardan en un bloque compacto y ordenado de RAM, no desperdigados con punteros como en una lista. El procesador puede recorrerlos de corrido.
3. **Opera vectorizado**: las operaciones aritméticas se aplican a todo el array de una sola vez, apoyándose en instrucciones de bajo nivel del procesador.

```{python}
#| label: array-basico
a = np.array([10, 20, 30, 40])

print("Array:   ", a)
print("Tipo:    ", type(a))
print("dtype:   ", a.dtype)     # tipo de los elementos
print("shape:   ", a.shape)     # forma (dimensiones)
print("ndim:    ", a.ndim)      # cantidad de dimensiones
print("size:    ", a.size)      # cantidad total de elementos
```

El **`dtype`** (data type) es un concepto clave: le dice a NumPy exactamente cuántos bytes ocupa cada número y cómo interpretarlos. En finanzas trabajamos casi siempre con `float64` (números reales de doble precisión), que es el default para decimales.

::: {.callout-note title="shape: la forma manda"}
El atributo `.shape` es una tupla que describe las dimensiones. Un vector de 4 elementos tiene shape `(4,)`; una matriz de 3 filas por 2 columnas tiene shape `(3, 2)`. Cuando algo falla en NumPy, el 90% de las veces es un problema de shapes que no encajan. Acostumbrate a mirar `.shape` como primer paso de debugging.
:::

## Crear arrays

Rara vez vas a escribir los números a mano. NumPy trae funciones para generar los arrays más comunes:

```{python}
#| label: creacion
# Desde una lista
np.array([1.0, 2.0, 3.0])

# Rango de valores (como range, pero array): inicio, fin (excluido), paso
plazos = np.arange(0, 12, 3)          # [0, 3, 6, 9] meses
print("arange:  ", plazos)

# N valores equiespaciados entre dos extremos (útil para grillas)
grilla = np.linspace(0, 1, 5)         # 5 puntos entre 0 y 1
print("linspace:", grilla)

# Arrays de ceros y unos (útiles para inicializar acumuladores)
print("zeros:   ", np.zeros(4))
print("ones:    ", np.ones(3))

# Matriz identidad (aparecerá en álgebra de portafolios)
print("identidad:\n", np.eye(3))
```

## Arrays de varias dimensiones

Un vector es 1D; una **matriz** es 2D. En finanzas la matriz más importante es el **panel de retornos**: filas = fechas, columnas = activos.

```{python}
#| label: matriz
# Retornos mensuales de 3 activos durante 4 meses (4 filas x 3 columnas)
R = np.array([
    [0.02, -0.01,  0.03],
    [0.01,  0.02, -0.02],
    [-0.03, 0.01,  0.04],
    [0.02,  0.00,  0.01],
])

print("Panel de retornos:\n", R)
print("\nShape:", R.shape, "→ 4 fechas, 3 activos")
```

# Números aleatorios: el generador moderno

Buena parte de las finanzas computacionales consiste en simular escenarios, y para eso necesitamos números aleatorios. NumPy recomienda hoy usar un **generador** explícito, creado con `np.random.default_rng()`. Le pasamos una **semilla** (`seed`) para que los resultados sean reproducibles: la misma semilla da siempre los mismos "azares", lo cual es fundamental para que tus ejemplos y los de tus compañeros coincidan.

```{python}
#| label: random
rng = np.random.default_rng(seed=42)

# 5 retornos diarios simulados: media 0.05%, desvío 1.5%
retornos_sim = rng.normal(loc=0.0005, scale=0.015, size=5)
print("Retornos simulados:", retornos_sim)

# Una matriz 3x3 de números uniformes entre 0 y 1
print("\nUniformes:\n", rng.random((3, 3)))
```

::: {.callout-warning title="Vas a ver `np.random.seed()` en código viejo"}
Mucho código (y capítulos previos de versiones anteriores de este libro) usa el estilo antiguo `np.random.seed(42)` y `np.random.normal(...)`. Funciona, pero está considerado *legacy*. El estilo moderno con `default_rng()` es más robusto y es el que vas a encontrar en la documentación actual. Usá `rng.` de acá en adelante.
:::

# Indexado, slicing y máscaras booleanas

Acceder a partes de un array es donde NumPy se pone realmente potente.

## Slicing básico

Funciona como en las listas, con `[inicio:fin:paso]`, pero se extiende a varias dimensiones separando con comas: `matriz[filas, columnas]`.

```{python}
#| label: slicing
# Usamos el panel R de antes
print("Primera fila (retornos de la fecha 0):", R[0])
print("Primera columna (activo 0 en el tiempo):", R[:, 0])
print("Submatriz (2 primeras fechas, 2 primeros activos):\n", R[:2, :2])
print("Último retorno del último activo:", R[-1, -1])
```

La coma es la clave: `R[:, 0]` significa "todas las filas, columna 0". Poder pedir una columna entera de un panel sin bucles es exactamente lo que necesitamos para analizar un activo a lo largo del tiempo.

## Máscaras booleanas: filtrar por condición

Esta es una de las herramientas más usadas en análisis financiero. Una comparación sobre un array devuelve un array de `True`/`False`, y podemos usar ese array como "filtro":

```{python}
#| label: mascaras
retornos_diarios = np.array([0.012, -0.008, 0.003, -0.021, 0.015, -0.004])

# La comparación genera una máscara booleana
mascara_perdidas = retornos_diarios < 0
print("Máscara (días con pérdida):", mascara_perdidas)

# Usamos la máscara para quedarnos solo con esos elementos
perdidas = retornos_diarios[mascara_perdidas]
print("Retornos negativos:        ", perdidas)

print(f"\nDías con pérdida: {mascara_perdidas.sum()} de {retornos_diarios.size}")
print(f"Pérdida promedio: {perdidas.mean():.2%}")
```

Fijate el truco de `mascara_perdidas.sum()`: como `True` vale 1 y `False` vale 0, sumar una máscara booleana **cuenta cuántas condiciones se cumplen**. Es un patrón que vas a repetir mil veces (¿cuántos días superaron el VaR?, ¿cuántos activos rindieron más que el mercado?, etc.).

# Vectorización: pensar en vectores, no en bucles

Ya vimos la idea con los retornos. Generalicémosla. Las operaciones aritméticas (`+`, `-`, `*`, `/`, `**`) y las funciones de NumPy (`np.log`, `np.exp`, `np.sqrt`...) se aplican **elemento a elemento** sobre todo el array.

```{python}
#| label: vectorizacion
precios = np.array([100.0, 102.5, 101.0, 103.5, 105.0])

# Retorno logarítmico: r_t = ln(P_t / P_{t-1}), en una línea
ret_log = np.log(precios[1:] / precios[:-1])
print("Retornos log:", ret_log)

# Convertir un vector entero de tasas anuales a mensuales, todo de una
tasas_anuales = np.array([0.40, 0.35, 0.50, 0.45])
tasas_mensuales = (1 + tasas_anuales) ** (1/12) - 1
print("Tasas mensuales equivalentes:", np.round(tasas_mensuales, 4))
```

::: {.callout-tip title="La regla de oro"}
Si te encontrás escribiendo un `for` que recorre un array para hacer una cuenta en cada elemento, casi siempre hay una versión vectorizada más corta y mucho más rápida. Antes de escribir el bucle, preguntate: *"¿puedo aplicarle esto al array entero?"*
:::

## ¿Cuánto más rápido es, en serio?

No es una diferencia cosmética. Comparemos sumar el cuadrado de un millón de números con un bucle de Python contra NumPy:

```{python}
#| label: benchmark
import time

datos = rng.normal(size=1_000_000)

# Versión con bucle Python
t0 = time.perf_counter()
suma = 0.0
for x in datos:
    suma += x**2
t_bucle = time.perf_counter() - t0

# Versión vectorizada
t0 = time.perf_counter()
suma_np = np.sum(datos**2)
t_numpy = time.perf_counter() - t0

print(f"Bucle Python:  {t_bucle*1000:7.1f} ms")
print(f"NumPy:         {t_numpy*1000:7.1f} ms")
print(f"NumPy es ~{t_bucle/t_numpy:.0f}x más rápido")
```

Sobre un millón de datos la diferencia es de uno a dos órdenes de magnitud. En una simulación de Monte Carlo con millones de trayectorias (Capítulo 13), esto es la diferencia entre que tu código termine en segundos o en horas.

¿De dónde sale esa diferencia? Del **trabajo repetido que hace el intérprete**. En el bucle de Python, *cada una* del millón de vueltas repite la misma burocracia: mirar qué tipo tiene `x` (¿es int? ¿float? ¿string?), desempaquetar el valor del objeto que lo envuelve, decidir qué operación "elevar al cuadrado" corresponde a ese tipo, ejecutarla, y volver a empaquetar el resultado en un objeto nuevo. Un millón de elementos, un millón de veces la misma verificación. NumPy hace esa burocracia **una sola vez**: como el array es homogéneo (todos `float64`, gracias al `dtype`), sabe de antemano qué operación aplicar a todos, y delega el recorrido a un bucle compilado en C que barre la memoria contigua a toda velocidad — incluso procesando varios elementos por instrucción del procesador (SIMD). No es que Python "sea lento": es que le pedimos que vuelva a deducir lo obvio un millón de veces. La vectorización es, en el fondo, **mover la decisión fuera del bucle**.

# Reducciones: resumir un array

Una **reducción** toma muchos números y devuelve pocos: la suma, el promedio, el máximo, el desvío. Son la base de toda la estadística descriptiva.

```{python}
#| label: reducciones
ret = np.array([0.012, -0.008, 0.003, -0.021, 0.015, -0.004])

print(f"Suma (retorno acumulado aprox): {ret.sum():.4f}")
print(f"Media:                          {ret.mean():.4f}")
print(f"Desvío estándar (volatilidad):  {ret.std():.4f}")
print(f"Mínimo (peor día):              {ret.min():.4f}")
print(f"Máximo (mejor día):             {ret.max():.4f}")
```

## El parámetro `axis`: el concepto que más confunde (y más importa)

Cuando reducimos una **matriz**, tenemos que decidir *en qué dirección* resumimos. Ahí entra `axis`:

- `axis=0` colapsa las **filas** → un resultado **por columna** (por activo).
- `axis=1` colapsa las **columnas** → un resultado **por fila** (por fecha).

Con un panel de retornos (filas = fechas, columnas = activos), esto es exactamente lo que necesitamos:

```{python}
#| label: axis
# Panel: 4 fechas x 3 activos
R = np.array([
    [0.02, -0.01,  0.03],
    [0.01,  0.02, -0.02],
    [-0.03, 0.01,  0.04],
    [0.02,  0.00,  0.01],
])

# Retorno medio DE CADA ACTIVO → colapsamos las fechas (axis=0)
print("Media por activo (axis=0):", R.mean(axis=0))

# Volatilidad DE CADA ACTIVO
print("Vol por activo   (axis=0):", R.std(axis=0))

# Retorno DE CADA FECHA (un portafolio equiponderado, por ejemplo) → axis=1
print("Media por fecha  (axis=1):", R.mean(axis=1))
```

::: {.callout-note title="Truco para no confundirte con axis"}
`axis=0` "apunta hacia abajo" (recorre las filas y deja una fila-resumen), así que el resultado tiene tantos elementos como **columnas**. Regla mnemotécnica: el eje que ponés en `axis` es el que **desaparece** del shape. Si `R.shape` es `(4, 3)`, entonces `R.mean(axis=0).shape` es `(3,)`.
:::

# Broadcasting: operar arrays de distinta forma

¿Qué pasa si querés sumarle un número a todo un array, o restarle a cada columna su propia media? NumPy tiene una regla elegante llamada **broadcasting**: cuando las formas no coinciden, NumPy "estira" automáticamente el array más chico para que encajen, sin copiar datos de verdad.

El caso más simple ya lo usaste sin darte cuenta:

```{python}
#| label: broadcast-escalar
precios = np.array([100.0, 102.5, 101.0])

# Sumar un escalar a un vector: el escalar se "estira" a todos los elementos
print("Con impuesto del 1%:", precios * 1.01)
```

El caso poderoso es **normalizar un panel**: restarle a cada activo su media y dividir por su desvío (estandarización), una operación constante en modelos de factores y machine learning financiero.

```{python}
#| label: broadcast-panel
R = np.array([
    [0.02, -0.01,  0.03],
    [0.01,  0.02, -0.02],
    [-0.03, 0.01,  0.04],
    [0.02,  0.00,  0.01],
])

medias = R.mean(axis=0)   # shape (3,) → una media por activo
desvios = R.std(axis=0)   # shape (3,) → un desvío por activo

# R tiene shape (4,3) y medias shape (3,): broadcasting alinea por columna
R_estandarizado = (R - medias) / desvios

print("Medias por activo:", np.round(medias, 4))
print("\nPanel estandarizado (media 0, desvío 1 por columna):\n",
      np.round(R_estandarizado, 3))
print("\nVerificación — media de cada columna:", np.round(R_estandarizado.mean(axis=0), 10))
```

NumPy vio que `R` es `(4, 3)` y `medias` es `(3,)`, y entendió que tenía que restar `medias` **a cada fila**. No tuviste que escribir ningún bucle sobre las 4 fechas.

::: {.callout-warning title="Cuándo el broadcasting falla"}
El broadcasting solo funciona si las dimensiones son compatibles: o son iguales, o una de ellas es 1. Si intentás operar un `(4, 3)` con un `(4,)` vas a recibir un `ValueError: operands could not be broadcast together`. La solución suele ser reformar el vector a `(4, 1)` con `vector.reshape(-1, 1)` para que se alinee por fila en lugar de por columna. Cuando veas ese error, mirá los shapes.
:::

# Álgebra lineal: la antesala de Markowitz

Acá NumPy muestra para qué fue diseñado. La optimización de portafolios del Módulo 2 se escribe entera en lenguaje matricial, y NumPy lo implementa directo.

El **producto matricial** se hace con el operador `@` (no con `*`, que es elemento a elemento). Veamos el cálculo más importante de toda la teoría de portafolios: el **retorno esperado de un portafolio**, que es el producto entre el vector de pesos $\mathbf{w}$ y el vector de retornos esperados $\boldsymbol{\mu}$.

```{python}
#| label: producto-portafolio
# Pesos del portafolio (40% activo 1, 35% activo 2, 25% activo 3)
w = np.array([0.40, 0.35, 0.25])

# Retornos esperados anuales de cada activo
mu = np.array([0.12, 0.18, 0.08])

# Retorno esperado del portafolio: w · mu (producto punto)
ret_portafolio = w @ mu
print(f"Retorno esperado del portafolio: {ret_portafolio:.2%}")
```

Y ahora la estrella: la **matriz de covarianzas** $\Sigma$, que resume cómo se mueven juntos los activos y es el corazón de la medición de riesgo. NumPy la calcula con `np.cov`. Con ella, la **varianza del portafolio** es la forma cuadrática $\mathbf{w}^T \Sigma \mathbf{w}$:

```{python}
#| label: covarianza
# Panel de retornos: activos en FILAS, observaciones en COLUMNAS (rowvar=True, el default de np.cov)
rng = np.random.default_rng(7)
R_hist = rng.normal(loc=[0.001, 0.0015, 0.0008],
                    scale=[0.02, 0.03, 0.015],
                    size=(250, 3)).T   # .T → 3 activos x 250 días

# Matriz de covarianzas (3x3)
Sigma = np.cov(R_hist)
print("Matriz de covarianzas (Σ):\n", np.round(Sigma, 6))

# Varianza del portafolio: wᵀ Σ w
var_portafolio = w @ Sigma @ w
vol_portafolio = np.sqrt(var_portafolio)
print(f"\nVolatilidad diaria del portafolio: {vol_portafolio:.4f}")
print(f"Volatilidad anualizada:            {vol_portafolio * np.sqrt(252):.2%}")
```

Esas dos líneas —`w @ mu` y `w @ Sigma @ w`— son, literalmente, la Teoría Moderna de Portafolios. En el Capítulo 8 le vamos a pedir a la computadora que busque los pesos `w` que minimizan ese riesgo. Todo el andamiaje matemático ya lo tenés en NumPy.

El submódulo `np.linalg` completa el kit de álgebra lineal (inversas, determinantes, autovalores, resolución de sistemas):

```{python}
#| label: linalg
M = np.array([[4.0, 1.0],
              [1.0, 3.0]])

print("Inversa:\n", np.linalg.inv(M))
print("\nDeterminante:", np.linalg.det(M))
print("Autovalores: ", np.linalg.eigvals(M))
```

::: {.callout-note title="Guardá esto para más adelante"}
Black-Litterman (Capítulo 10) y la regresión por mínimos cuadrados (Capítulo 15) se resuelven invirtiendo matrices con `np.linalg.inv` y `np.linalg.solve`. El código que acabás de ver es la base de la mitad del libro.
:::

# De NumPy a Pandas

NumPy es potentísimo, pero tiene una limitación para el trabajo diario: los arrays no tienen **etiquetas**. En `R[:, 0]` vos sabés que la columna 0 es "el activo A" porque te lo acordás, no porque el array lo diga. Cuando manejás decenas de activos con fechas de por medio, eso se vuelve un problema.

Ahí entra **Pandas** (Capítulo 6): pone etiquetas (nombres de columnas y un índice de fechas) *encima* de los arrays de NumPy. Un `DataFrame` es, en el fondo, un array de NumPy con nombres. Por eso todo lo que aprendiste acá —vectorización, broadcasting, `axis`, máscaras booleanas— se traslada casi idéntico a Pandas. No estás aprendiendo dos cosas: estás aprendiendo NumPy, y Pandas es NumPy con etiquetas.

---

# Errores comunes

::: {.callout-warning title="Trampas frecuentes con NumPy"}
- **Confundir `*` con `@`**: `A * B` multiplica elemento a elemento; `A @ B` es el producto matricial. Para portafolios casi siempre querés `@`.
- **Copias vs. vistas**: un slice como `b = a[:2]` **no copia** los datos, es una *vista*. Si modificás `b`, modificás `a`. Si necesitás una copia independiente, usá `a[:2].copy()`.
- **Olvidarse del `axis`**: `R.mean()` sin `axis` promedia *todos* los elementos y te da un solo número, no uno por activo. Casi siempre querés especificar `axis`.
- **Enteros donde querías decimales**: `np.array([1, 2, 3])` crea un array de enteros; dividirlo puede truncar en algunos contextos. Escribí `1.0` o pasá `dtype=float` para asegurarte de trabajar con `float64`.
:::
