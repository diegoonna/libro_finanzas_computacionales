6  Capítulo 4: Programación Orientada a Objetos (POO)

Paradigmas, Estructuras y Diseño de Modelos Financieros

Resumen

Introducimos la POO como paradigma fundamental para modelar instrumentos financieros. Exploramos la anatomía de los objetos, el ciclo de vida, herencia, composición y las mejores prácticas de diseño como el principio de responsabilidad única (SRP).

7 Paradigmas de Programación

Un paradigma de programación es un enfoque o estilo fundamental para resolver problemas estructurando el código de una manera particular. No hay un paradigma “correcto”, sino diferentes herramientas para diferentes tareas.

7.1 Tipos Principales

  1. Paradigma Imperativo: Se basa en secuencias de instrucciones que modifican el estado del programa paso a paso (ej. bucles for y asignaciones directas).
  2. Paradigma Funcional: Usa funciones puras, evitando estados mutables y datos que cambian (visto en el Capítulo 3 con recursión y funciones de orden superior).
  3. Programación Orientada a Objetos (POO): Modela elementos del mundo real como entidades que agrupan datos y comportamiento.

8 Introducción a la POO

8.1 Motivación

Resulta natural estructurar los programas pensando en elementos del mundo real (acciones, bonos, carteras) que tienen propiedades (nombre, precio) y comportamientos (valorizarse, pagar dividendos). Esta abstracción hace que el código sea más modular, intuitivo y fácil de reutilizar.

8.2 Clases y Objetos

  • Clase: Funciona como una plantilla o blueprint que define los atributos y acciones que tendrán en común los objetos.
  • Objeto (Instancia): Son las representaciones concretas construidas a partir de una clase. Cada objeto tiene sus propios valores específicos.

9 Anatomía de un Objeto

Un objeto se define por tres componentes fundamentales:

  1. Atributos: Propiedades o datos que describen el estado del objeto (sustantivos: ticker, precio, cantidad).
  2. Métodos: Comportamientos o acciones que el objeto es capaz de realizar (verbos: comprar(), calcular_vencimiento()).
  3. Estado: Refiere al conjunto de valores que tienen los atributos de un objeto en un momento puntual de la ejecución.
class Accion:
    def __init__(self, ticker, precio):
        self.ticker = ticker   # Atributo (Sustantivo)
        self.precio = precio   # Atributo (Sustantivo)

    def actualizar_precio(self, nuevo_precio): # Método (Verbo)
        self.precio = nuevo_precio

10 Diseño Orientado a Objetos y Encapsulación

10.1 Diseño (OOD)

Consiste en dividir un sistema complejo en componentes o “cajas negras” más pequeñas que se comunican entre sí a través de interfaces claras.

10.2 Encapsulación

Es el concepto de ocultar la complejidad interna de la implementación y exponer al exterior únicamente los métodos necesarios para interactuar con la clase. Esto protege la integridad de los datos.

En Python, todo es un objeto. Un simple string ("AAPL"), un entero (100) o una lista ya vienen con sus propios métodos integrados (ej: .upper(), .append()).

11 Implementación Práctica en Python

Utilizamos la palabra reservada class para definir la plantilla.

11.1 El parámetro self

Es indispensable en la definición de métodos de instancia. Funciona como una referencia al objeto particular que está ejecutando la acción, permitiéndole acceder a sus propios atributos y métodos.

11.2 Interacción entre Objetos

Es posible pasar objetos como parámetros a los métodos de otros objetos, permitiendo que interactúen y modifiquen sus estados mutuamente.

class Orden:
    def __init__(self, accion, cantidad):
        self.accion = accion  # Recibe un objeto de tipo Accion
        self.cantidad = cantidad
    
    def ejecutar(self):
        monto = self.accion.precio * self.cantidad
        print(f"Ejecutando orden de {self.cantidad} {self.accion.ticker} por ${monto:,.2f}")

apple = Accion("AAPL", 175.50)
orden_compra = Orden(apple, 10)
orden_compra.ejecutar()
Ejecutando orden de 10 AAPL por $1,755.00

12 Ciclo de Vida de los Objetos

  1. Constructor (__init__): Método especial que se ejecuta automáticamente al instanciar el objeto. Se usa para inicializar atributos.
  2. Destructor (__del__): Se ejecuta automáticamente cuando el objeto es descartado de la memoria por el recolector de basura de Python.
class ConexionMercado:
    def __init__(self):
        print("Abriendo conexión con el mercado...")
        
    def __del__(self):
        print("Cerrando conexión y liberando recursos.")

# Al crear y luego borrar la referencia
conn = ConexionMercado()
del conn
Abriendo conexión con el mercado...
Cerrando conexión y liberando recursos.

13 Tipos de Atributos

  • Atributos de Clase: Definidos a nivel de plantilla. Su valor es compartido por todas las instancias.
  • Atributos de Instancia: Definidos a través de self. Sus valores son únicos e independientes para cada objeto.
class Bono:
    mercado = "BYMA"  # Atributo de clase (compartido)
    
    def __init__(self, ticker):
        self.ticker = ticker # Atributo de instancia (único)

b1, b2 = Bono("GD30"), Bono("AL30")
print(f"{b1.ticker} y {b2.ticker} cotizan en {Bono.mercado}")
GD30 y AL30 cotizan en BYMA

14 Relaciones entre Clases

14.1 Composición (“Tiene un”)

Un objeto guarda a otro objeto distinto como uno de sus atributos. Ejemplo: Un Portafolio tiene una lista de Acciones.

14.2 Herencia (“Es un”)

Una subclase toma prestados todos los métodos y atributos de una superclase. Evita duplicación de código. Ejemplo: Un Bono Corporate es un Bono.

14.2.1 Función super()

Se utiliza para invocar métodos de la clase padre (especialmente el constructor) sin tener que reescribirlo.

14.3 Polimorfismo

Capacidad del código para usar un mismo nombre de método pero ejecutar rutinas distintas según el tipo de objeto que realice la llamada.

class Instrumento:
    def calcular_valor(self):
        pass

class AccionFinanciera(Instrumento):
    def __init__(self, ticker, precio):
        self.ticker = ticker
        self.precio = precio
    def calcular_valor(self):
        return self.precio

class BonoFinanciero(Instrumento):
    def __init__(self, ticker, valor_nominal, paridad):
        self.ticker = ticker
        self.valor_nominal = valor_nominal
        self.paridad = paridad
    def calcular_valor(self):
        return self.valor_nominal * self.paridad

# Polimorfismo en acción
cartera = [AccionFinanciera("AAPL", 170), BonoFinanciero("GD30", 100, 0.35)]
for i in cartera:
    print(f"Valor de {i.ticker}: ${i.calcular_valor():.2f}")
Valor de AAPL: $170.00
Valor de GD30: $35.00

15 Buenas Prácticas

  1. Nomenclatura Coherente:
    • Clases: Sustantivos en singular y Mayúsculas (PascalCase). Ej: CalculadoraBonos.
    • Métodos: Verbos en minúscula (snake_case). Ej: obtener_precio().
  2. Visibilidad por Convención:
    • _atributo: Protegido (uso interno sugerido).
    • __atributo: Privado (ocultamiento fuerte).
  3. Principio SRP (Single Responsibility Principle): Cada clase y cada método debe tener una única responsabilidad clara. Si una clase hace demasiadas cosas, debe dividirse.

3.  **Estado**: Refiere al conjunto de valores que tienen los atributos de un objeto en un momento puntual de la ejecución.
